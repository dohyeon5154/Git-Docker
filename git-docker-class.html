1교시 · GIT 기초

파일은 세 개의 방을 지나 기록된다

Git의 명령어를 외우기 전에, 파일이 어디에 있는지를 먼저 봅니다. 파일을 골라 명령을 실행하면 어느 방에서 어느 방으로 옮겨지는지 그대로 보입니다.

다루는 것

  • 세 개의 영역 — 작업 디렉터리 · 스테이징 · 저장소
  • add 는 옮기고, commit 은 기록한다
  • restore 로 되돌리는 두 방향
  • reset 3형제의 차이 — 어디까지 되돌리는가
  • .gitignore 로 추적에서 빼기
수업 목표커밋을 만들고, 잘못 만든 커밋을 되돌릴 수 있다.

2교시 · 브랜치와 병합

그래프의 모양이 병합 방식을 결정한다

fast-forward와 3-way 병합은 옵션이 아니라 결과입니다. 커밋을 어디에 쌓았는지에 따라 Git이 알아서 다른 길을 고릅니다. 직접 쌓아 보며 확인합니다.

다루는 것

  • 브랜치는 커밋을 가리키는 이름표일 뿐
  • HEAD 가 지금 어디를 보고 있는가
  • fast-forward vs 3-way merge
  • 충돌은 같은 줄을 양쪽에서 고쳤을 때만
  • stash 로 작업 잠시 치워두기
수업 목표브랜치를 나누고 충돌을 직접 해결할 수 있다.

3교시 · 원격 저장소와 협업

origin/main 은 원격이 아니라 내 컴퓨터의 메모다

push가 거절되는 이유, fetch와 pull이 다른 이유는 세 저장소의 위치 관계 하나로 전부 설명됩니다. 동료가 먼저 push한 상황을 만들어 확인해 보세요.

다루는 것

  • clone push fetch pull 의 방향
  • fetch = 가져오기, pull = 가져와 합치기
  • push 거절(non-fast-forward)이 뜨는 조건
  • Pull Request 흐름과 코드 리뷰
  • 브랜치 전략 — GitHub Flow
수업 목표충돌 없이 팀과 코드를 주고받을 수 있다.

다루는 것

5교시 · Dockerfile

한 줄이 바뀌면 그 아래는 전부 다시 만든다

Dockerfile은 위에서 아래로 층을 쌓습니다. 무엇을 위에 두느냐에 따라 빌드가 0.5초로 끝나기도, 25초가 걸리기도 합니다. 같은 수정을 두 순서에 동시에 적용해 봅니다.

다루는 것

  • FROM WORKDIR COPY RUN CMD
  • 레이어 캐시와 명령어 순서 최적화
  • .dockerignore 로 빌드 문맥 줄이기
  • 볼륨 — 컨테이너보다 오래 사는 데이터
  • 태그 규칙과 이미지 배포
수업 목표내 앱을 이미지로 만들고, 빠르게 다시 만들 수 있다.

6교시 · Compose와 실전 활용

다루는 것

  • 서비스 · 네트워크 · 볼륨의 관계
  • up -d down logs -f
  • 컨테이너끼리는 서비스 이름으로 부른다
  • 멀티스테이지 빌드로 이미지 줄이기
  • 자주 만나는 에러와 해결 순서
수업 목표여러 컨테이너로 개발 환경을 한 번에 띄울 수 있다.
